## Execution rules

- Follow the user's current instructions first. State material assumptions and resolve conflicting requirements before implementation.
- Use Bun for JavaScript tooling and Expo's SDK-compatible package installation. If Python is needed, use uv.
- Keep the user-requested Expo SDK 58. Do not silently downgrade it. Use the versions in package.json and bun.lock.
- Reuse the existing starter. Work through the plan's dependencies; do not scaffold over the repository or implement all units merely because a document references them.
- Design native document identity, revision checks, and recovery boundaries before adding convenience features. Preserve Markdown and never execute template or note content as code.
- Use disposable fixtures for development. Never require access to a contributor's personal vault or iCloud account for the baseline checks.
- Reproduce bugs through the closest available end-to-end flow before fixing them. Run meaningful tests and inspect UI where the environment supports it; record unavailable coverage honestly.
- Use lowercase comments and conventional lowercase commit messages. Do not add co-author signatures. Commit completed tasks or implementation units.
- Do not manually edit generated native files or changelogs. Express native configuration through the Expo app configuration or config plugins.
- Keep local file links relative to the repository. New required assets and reference documents must be committed or reproducibly generated by a committed script. Proposed implementation paths must be labeled as future work, not claimed as existing dependencies.
- Keep real journal content, credentials, personal paths, and device grants out of this public repository unless the user explicitly approves the specific publication.

## Verification

Run `bun install --frozen-lockfile`, `bun run check`, and `bunx expo install --check`. Run `bun run export` when changing code, dependencies, or build configuration. Documentation changes need the reference check and diff review. Add behavioral tests with feature implementation; the current starter has no completed vault/editor feature tests.

Record the environment and distinguish JS bundle export, native compilation, simulator interaction, physical-device performance, and multi-device iCloud tests. One passing category does not prove the others.
